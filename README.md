# Zulu A7

Zulu A7 is a USB FPGA board built around an AMD/Xilinx Artix-7
XC7A35T-1CPG236C. An FTDI FT2232HL bridge provides JTAG (channel A) and a
UART (channel B) over one micro-USB port. The board carries 64 MB of SDRAM,
a 128 Mbit quad-SPI configuration flash, a microSD socket, a Pmod host
header and a 40-pin breadboard header. It runs from USB through a
single-cell LiPo charger with power path and three buck regulators (3.3 V,
1.8 V and 1.0 V). The PCB is a 69.85 x 25.40 mm, six-layer HDI board.

The main design is the Altium Designer project in `Zulu_Altium_VS_Code/`.
Its fabrication and turnkey-assembly packages for PCBWay are dated
2026-10-07. Build and test results are not recorded in this repository.

Zulu A7 is an adaptation of **XuLA2**, the USB FPGA prototyping board by

XESS's [product listing](https://www.tindie.com/products/xesscorp/xula2-lx25-fpga-prototyping-board/)
says the whole XuLA2 design was made open source and that anyone who
re-designs it must open-source their design too. As of 2026-10-07 it lists
XuLA2 as retired. The licence terms are those of CC BY-SA 3.0.

XuLA2 (schematic version 2.0, EAGLE 5 files) had a Xilinx Spartan-6
XC6SLX25 in FT256 and a Microchip PIC18F14K50 that handled reset and
initialisation, clock generation and USB-to-JTAG. It also had 256 Mbit
SDRAM, 8 Mbit SPI flash, a microSD socket, a mini-USB connector, ZLDO1117
3.3 V and 1.2 V regulators, a 40-pin breadboard prototyping header and an
aux JTAG header.

### Main changes from XuLA2

| | XuLA2 | Zulu A7 |
|---|---|---|
| FPGA | Xilinx Spartan-6 XC6SLX25, FT256 | AMD/Xilinx Artix-7 XC7A35T-1CPG236C |
| USB bridge | Microchip PIC18F14K50 | FTDI FT2232HL with a 93LC46B EEPROM |
| USB connector | Hirose UX60SC-MB-5ST mini-USB | Molex 105017-0001 micro-USB |
| SDRAM | W9825G6JH-5, 256 Mbit | Alliance AS4C32M16SB-7TCN, 512 Mbit |
| Flash | W25Q80BV, 8 Mbit | Winbond W25Q128JV, 128 Mbit quad SPI |
| microSD | ALPS SCHD3A0100 | Hirose DM3D-SF |
| Clock | generated by the PIC18F14K50 | 12.000 MHz oscillator shared by the FT2232HL and the FPGA |
| Power | ZLDO1117 3.3 V and 1.2 V regulators | BQ24232 LiPo charger and three SC189 bucks (3.3 / 1.8 / 1.0 V) |
| Headers | 40-pin breadboard header, aux JTAG header | 40-pin breadboard header X2 with its own pin map, 2x6 Pmod host header J1, unpopulated JTAG holes JP3/JP4 |
| PCB | 2 in x 1 in | 69.85 x 25.40 mm, six-layer HDI |

XuLA3 and the EAGLE-era Zulu A7 used an LTC3569 triple buck. The Altium
copy replaced it on 2026-09-06 with the three SC189 bucks, so the EAGLE
files in this repository still show the LTC3569.

`docs/Zulu_A7-Design-Change-Record.html` lists the part changes from the
fork. Its "Was" column is the XuLA3 rev 1 state, which is mostly but not
entirely the XuLA2-LX25 BOM (the ESP8266 header and the BTN1 PTA-142 button
were XuLA3 additions). It predates the SC189 power section.

## Board facts

- **FPGA**: U1 XC7A35T-1CPG236C, CPG236 BGA, 10 x 10 mm, 0.5 mm pitch.
- **USB**: U2 FTDI FT2232HL (LQFP-64). Channel A is MPSSE JTAG plus
  PROG#/DONE, channel B is the UART. U10 93LC46B configuration EEPROM.
  X1 Molex 105017-0001 micro-USB-B.
- **Memory**: U3 Alliance Memory AS4C32M16SB-7TCN, 512 Mbit (64 MB) SDRAM;
  the memory controller must use 10 column bits (A0-A9). U4 Winbond
  W25Q128JVSIQ, 128 Mbit quad SPI; the 17,536,096-bit bitstream leaves about
  14 MB for user data.
- **Clock**: Q1 ECS-3225SMV-120-FP-TR, 12.000 MHz, +-10 ppm HCMOS
  oscillator, driving the FT2232HL and the FPGA through 33 ohm each.
- **Power**: U8 TI BQ24232 single-cell LiPo charger with power path. Its
  output VU, the system rail that feeds the three bucks, is 4.4 V from USB
  and VBAT - 60 mV on battery; 495 mA input limit, 244 mA charge current.
  Battery on X4, a JST PH 2-pin header (pin 1 = battery +); the BOM has no
  battery. U5, U6 and U7 are Semtech SC189 bucks for 3.3 V, 1.8 V and 1.0 V
  (FPGA core).
- **I/O**: X2 40-pin breadboard header, 2.54 mm pitch, rows 22.86 mm apart,
  mounted from the underside; GND on pins 1, 17 and 21, +3.3 V on 18,
  +1.8 V on 19, +1.0 V on 20, VU on 22. J1 2x6 Pmod host header. X3 Hirose
  DM3D-SF microSD socket with card detect. JP3/JP4 unpopulated 1x3 JTAG
  holes. User button BTN, RGB LED LD0 and five 0603 LEDs (LD1-LD5).
- **PCB**: 69.85 x 25.40 mm, six layers (Top / L2 GND / L3 / L4 / L5 VCC3V3 /
  Bottom). Two-step HDI 1+1+N+1+1 with 0.15 mm laser microvias, 0.15 mm
  L3-L4 buried vias and 0.20 mm through vias. 3.0 / 3.5 mil minimum
  track / space. USB pair 90 ohm differential.
- **Status**: fully routed. Altium DRC on the final saved board (2026-10-07
  16:53) reports 0 violations; the report is
  `Zulu_Altium_VS_Code/Imported zulu_a7.PrjPcb/Design Rule Check - zulu_a7.drc`.
  The release packages identify the board by its PcbDoc SHA-256,
  `89a421b9060195d66bed82f7a4e7d80121bd0e9d679a3fee32289e8f541f4bde`.
- **Assembly**: 172 fitted designators (32 top, 140 bottom), 76 parts in
  0201. ENIG finish recommended. No fiducials on the board.

Known caveats, from `Zulu_Altium_VS_Code/docs/power_budget.md` and the
assembly notes:

- The worst-case draw (about 697 mA) exceeds the 495 mA input limit and needs
  the battery; with no battery the board browns out at that load. The board
  draws more than 100 mA before the FT2232HL enumerates.
- Every rail has more output capacitance than the SC189 datasheet's 30 uF
  start-up limit. Scope the three rails at power-on on the first board.
- LD0 green and blue are sunk from 3.3 V through 33 ohm and may be dim or
  dark; only red has margin.
- U5 and U7 look alike; swapping them puts 3.3 V on the FPGA core.

## Where to start

1. Open `Zulu_Altium_VS_Code/Imported zulu_a7.PrjPcb/zulu_a7.PrjPcb` in
   Altium Designer. The folder name comes from the EAGLE Import Wizard.
2. `Zulu_Altium_VS_Code/fabrication/PCBWAY_FAB_NOTES.txt`: what the current
   board is (stack, vias, impedance, outline, file map, final DRC).
3. `Zulu_Altium_VS_Code/assembly/Zulu_A7_Assembly_Notes.txt` and
   `Zulu_Altium_VS_Code/docs/pcbway_assembly_release.md`: the assembly
   release. To regenerate it, run
   `python tools/generate_jlcpcb_assembly.py --release-date 2026-10-07` from
   `Zulu_Altium_VS_Code/`.
4. `docs/zulu_a7-bom.csv`: the master BOM. Regenerate it only with
   `Zulu_Altium_VS_Code/tools/master_bom.py`; the copies in `Zulu_Altrium/`
   and `Altium_backup/` read stale sheets.
5. `Zulu_Altium_VS_Code/docs/power_budget.md`: power path, current budget
   and the caveats above.
6. `Zulu_Altium_VS_Code/docs/stage13_route_plan.md`, section "Final
   implementation closeout": how routing was finished. Later board changes
   are in `x1_slot_fix.md`, `x2_power_pins.md`, `x2_pin_labels.md` and
   `btn_move.md` in the same folder.
7. For FPGA work: `vivado/zulu_a7_pins.xdc` is the current pin map (the
   SDRAM ports need DRIVE 8, as set there). This repository has no
   programming instructions, FT2232H EEPROM image or example bitstream.
8. `Zulu_Altium_VS_Code_HDI_Optimized/HDI_OPTIMIZATION_NOTES.md` (the
   derivative board) and `Zulu_kicad/CONVERSION.md` (the KiCad copy).

Notes:

- No current schematic PDF is tracked. The `zulu_a7.pdf` files in
  `Zulu_Altrium/` and `Altium_backup/` are 2026-09-10 prints and are out of
  date.
- `Zulu_Altium_VS_Code/docs/` is a dated record of stages and decisions, and
  older entries describe superseded states. For example,
  `Zulu_Altium_VS_Code/docs/hdi_spec.md` and `board/pcbway/README.md` name
  JLCPCB as the fab. Where they disagree with the release files, the release
  files are current.
- `Zulu_Altium_VS_Code/tools/README.md` covers the import, schematic-edit and
  audit scripts (`pip install olefile pywin32`). It does not cover the
  routing toolkits or the assembly generator, which also needs `pymupdf` and
  `altium-monkey` (`pip install olefile pymupdf altium-monkey`).
- Vendor datasheets are not tracked. After a fresh clone, put AMD's package
  pinout file for the XC7A35T-CPG236 back as
  `Datasheet/xc7a35tcpg236pkg_pinout.txt`. Without it, `tools/validate.py`,
  `tools/vivado_io_check.py`, `tools/escape/rings.py` and
  `tools/change_record.py`, and the Altium copy's `tools/bom_audit.py`,
  `tools/connectivity_check.py` and `tools/stage13/xdc_check.py`, lose their
  ball checks or fail.
