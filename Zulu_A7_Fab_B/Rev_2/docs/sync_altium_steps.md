Rules for running any script in Altium:

- Use File > Run Script > Browse > From file and pick the **`.PrjScr`**. Altium caches a `.pas` it has already
  compiled, so a procedure added to that file afterwards is silently not run.
- Each script checks that the focused document is
  `...\Zulu_A7_Fab_B\Rev_2\Imported zulu_a7.PrjPcb\zulu_a7_fab_b.PcbDoc`. It also checks the board's file name.
- Each script either refuses with `Refusing: ... NOTHING was changed.` plus a list of what failed, or runs.
- If the check after a run fails, the script says `DO NOT SAVE ...`. In that case close the PcbDoc **without
  saving** and reopen it.
- A `ShowMessage` can appear several seconds after the edit has landed.
- If a script halts with an Altium error, click OK and then press Ctrl+F3 (Run > Stop).

## What each script checks

**FabB_SyncPlace**

- Before moving anything it checks all of the following:
  - U2, X4, U10, U4, R34, C87, C88, C94, C99, C106 and R1 sit at their pre-sync origin, rotation and side (0.002 mm).
    These are the positions in `sync_data.json`.
  - Each part has the no-PMOD footprint and pad count (U2 65, X4 4, U10 8).
  - R119-R134 are R0201 parts parked more than 0.5 mm outside the outline.
  - All 139 pads carry the no-PMOD net. Unconnected pins are checked as no net.
  - U3's 16 DQ pads are on SDRAM-D0..D15.
  - U1's designator is still at (39.2168, 16.6251).
- Then it sets the side, the rotation and the absolute origin.
  - R119-R134 try the planned rotation and then +90, +180 and +270, until both pads land within 0.001 mm.
  - Positions are not relative moves.
- Then it sets every designator's NameOn/CommentOn and position as on the no-PMOD board.
  - This includes U1's designator at (39.70, 16.55), moved for R132.
  - A text that is off by more than 2 um is set to manual auto-position and moved with MoveToXY.
- Finally it re-measures all 139 pads and the 28 designators.

**FabB_SyncRules**

- It refuses if any of the three new rules already exists, or if `ComponentClearance` or `SolderMaskExpansion` is not
  there exactly once.
- It refuses unless there are exactly six Schematic Supply Nets rules, one per scope VCC1V0, GND, GNDADC, VCC1V8,
  VCC3V3 and VCCADC.
- It refuses unless SDRAM_DATA exists exactly once and holds D0..D15, every SDRAM-Dn net exists, X2, R131 and R132 are
  on the board, and U2 is the 65-pad FT2232HQ-QFN64.
- The two ComponentClearance rules are created in the no-PMOD order, so they get its priorities: X2 = 1,
  R131R132 = 2, the global rule = 3. SolderMaskExpansion_U2 gets priority 1.
- After adding the rules it reads back the gaps, the expansion, every voltage and every class member.

**FabB_SyncBodies**

- It checks that every bodied part sits at its predicted footprint, side, rotation and origin.
- The only bodies allowed beforehand are the ECO's library bodies on U2, X4, U10 and R119-R134, at most one each,
  with an outline box within 0.02 mm of the emitted box. These are kept.
- It adds the rest on Mechanical 13 as extruded boxes:
  - heights come from `body_heights.json`;
  - X2 gets four bottom housings;
  - J1 gets its footprint's Mechanical 7 outline.
- Afterwards it re-counts every part: X2 has 4 bodies, every other part 1, 200 in all.

**FabB_SyncRepour**

- It refuses unless the board has exactly 2 polygons. Then it rebuilds both.

**sync_altium_verify.py** (offline, on the saved file)

- `place`: footprint, side, rotation, origin, every pad position and net, NAMEON/COMMENTON and designator position,
  U3's DQ nets, and the outline.
- `rules`: the three new rules field by field, including PRIORITY; the shifted priorities of ComponentClearance and
  the SolderMaskExpansion rules; the six voltages; SDRAM_DATA equal to the no-PMOD 32 nets.
- `bodies`: per-part body count, outline (0.02 mm), height (0.001 mm), Mechanical 13 and projection.
